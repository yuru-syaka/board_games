 1. 目標と全体方針
================================================================================

【目標】
  - unityroom ではなく、自分のサイトの中でゲームを遊べるようにする
    （ゲーム一覧 → 紹介ページ → プレイページ、という BGA のような流れ）
  - オンライン対戦を PUN2（Photon Cloud）から AWS 上の自前サーバーに移す
  - 同時接続 100〜500 人を想定

【決めたこと】
  項目                 決定内容                                       理由
  -------------------  ---------------------------------------------  -----------------------------
  リージョン           東京（ap-northeast-1）を基本にする             利用者が日本にいるため
  インフラの管理       AWS CDK（TypeScript）でコード化               再現でき、変更履歴が残る
  ゲームサーバー       C#（ASP.NET Core）を ECS Fargate で動かす     ゲームのルールが Unity に依存しない
                       （当初の案の Colyseus / TypeScript は不採用）  C# で書かれており、そのまま使い回せる
  独自ドメイン         当初は後回し → 今回 boardgamepia.com を取得
  移行の進め方         段階的に（サイト配信 → サイト内プレイ →
                       サーバー → ログイン → 戦績）

【フェーズ（予定）】
  フェーズ 0  準備（アカウント、CLI、CDK、リポジトリ）           … 完了
  フェーズ 1  サイト内で遊べるようにする（S3 + CloudFront）       … ほぼ完了（自動デプロイは未）
  フェーズ 2  ゲームサーバーの試作（C# + ECS Fargate）            … 未着手
  フェーズ 3  ログインとロビー（Cognito）                         … 未着手
  フェーズ 4  戦績とレーティング（DynamoDB + API）                … 未着手

 2. AWS アカウントの準備（コンソールでの作業。あなたが実施）
================================================================================

2-1. ルートユーザーを守る
  - ルートユーザー（アカウント作成時のメールアドレスでのログイン）に MFA を設定
  - ルートユーザーのアクセスキーがないことを確認（確認結果: MFA 有効、アクセスキー 0 個）
  - 以後、ルートユーザーは請求関係などの特別な操作以外では使わない

2-2. AWS Budgets（月額アラート）
  - 予算名: monthly-total、月額 10 USD、毎月自動でリセット
  - 通知: 実績 50% / 実績 80% / 予測 100% の 3 段階でメール
  - 確認結果: 3 つの通知が設定済み
  - 補足: ドメインを購入した月は、ドメイン代の一括請求でアラートが届くことがある

2-3. IAM Identity Center（普段の作業用ログイン）
  - 東京リージョンで有効化
  - インスタンスの種類: 単一リージョンインスタンス
    （ゲームの利用者のログインは将来 Cognito で行うため、開発者用のログインに
      複数リージョンの冗長化は不要と判断）
  - AWS Organizations で有効化（組織インスタンス）
    → 組織が自動で作られ、このアカウントが「管理アカウント」になった
    → アカウントへのログイン権限（許可セット）を割り当てるために必要
  - グループ: Admins
  - ユーザー: toshiyuki（Admins に所属。招待メールからパスワードと MFA を設定）
  - 許可セット: AdministratorAccess（セッション 8 時間）
  - 割り当て: このアカウントに「Admins × AdministratorAccess」
  - 以後のコンソール作業は、AWS アクセスポータル（https://d-xxxxxxxxxx.awsapps.com/start）
    からログインして行う

2-4. Route 53 でドメインを購入（9 章）
  - boardgamepia.com を購入（自動更新オン、プライバシー保護オン）

 5. PUN2 の棚卸しとゲームサーバーの方針決定
================================================================================

  対象: C:\Users\nullg\createGame\boardGames の 5 本
        ghost_tic_tac_toe / Gobblet_Gobblers / Quarto / Geister / ButtleLine

  結果（詳細は docs/pun2-inventory.md）:

 6. サイト配信：S3 + CloudFront（WebStack）
================================================================================

  ファイル: infra/lib/web-stack.ts
  - S3 バケット（サイト用）
      公開アクセスはすべてブロック、暗号化、HTTPS 以外の通信を拒否
      デプロイ時に web/ の中身をアップロード（BucketDeployment。Lambda が自動で作られる）
  - CloudFront
      OAC（Origin Access Control）で、S3 は CloudFront からだけ読める
      HTTP → HTTPS へ転送、圧縮、キャッシュ（CachingOptimized）
      配信地域: PriceClass 200（日本を含む）
      CloudFront Function: "/blog/" を "/blog/index.html" に読み替える
  - 確認結果: 全ページが表示されること、S3 へ直接アクセスすると 403 で拒否されることを確認
  - 最初に作った空のスタック（BoardGamesStack）は不要になったので削除

 9. 独自ドメイン boardgamepia.com（Route 53 / CertStack）
================================================================================

  あなたが実施:
  - Route 53 で boardgamepia.com を購入（1 年、自動更新オン、プライバシー保護オン）
  - 購入と同時にホストゾーン boardgamepia.com が自動で作られた

  CDK で実施:
  - CertStack（us-east-1、infra/lib/cert-stack.ts）
      ACM の SSL 証明書: boardgamepia.com と www.boardgamepia.com
      検証用の DNS レコードを Route 53 に自動で追加（DNS 検証）。証明書は無料・自動更新
      us-east-1 にある理由: CloudFront は us-east-1 の証明書しか使えないため
  - WebStack の変更
      CloudFront に独自ドメイン（apex と www）と証明書を設定
      TLS 1.2 以上に制限（TLSv1.2_2021）。cloudfront.net の URL ではできなかった設定
      Route 53 に A / AAAA レコード（IPv4 / IPv6）を追加し、apex と www を CloudFront に向けた
      www.boardgamepia.com へのアクセスは https://boardgamepia.com/ へ 301 転送
        （CloudFront Function。パスとクエリは引き継ぐ）
      ホストゾーンは購入時のものを読み込んで使う（二重に作ると DNS が壊れるため）
  - web/ の OGP（SNS でシェアしたときのカード）の URL を https://boardgamepia.com/ に変更

  確認結果（2026-10-18）:
  - ドメインの登録: 完了（有効期限 2027-10-18、自動更新オン、プライバシー保護オン）
  - ネームサーバー: 外部の DNS（8.8.8.8）から Route 53 の 4 つが見えることを確認
  - DNS: boardgamepia.com の A（IPv4）、www.boardgamepia.com の AAAA（IPv6）が
    CloudFront のアドレスを返すことを確認
  - 証明書: 発行者 Amazon、対象 boardgamepia.com / www.boardgamepia.com、
    有効期限 2027-05（ACM が自動で更新）
  - https://boardgamepia.com/ のトップ・紹介ページ・ブログ・プレイページ・画像がすべて 200
  - http://boardgamepia.com/ → https://boardgamepia.com/ に 301 転送
  - https://www.boardgamepia.com/blog/?a=1 → https://boardgamepia.com/blog/?a=1 に 301 転送
    （パスとクエリが引き継がれる）
  - TLS 1.1 での接続は拒否され、TLS 1.2 では接続できることを確認
  - セキュリティヘッダー（HSTS など）が新しいドメインでも付いていることを確認
  - ブラウザで https://boardgamepia.com/ → PLAY → ゲームのタイトル画面まで表示され、
    コンソールにエラーがないことを確認

 13. 未完了の作業・注意点
================================================================================

  ★ あなたの対応が必要なもの
  - us-east-1 の通知メールの承認
      SNS（リージョン: 米国東部）→ サブスクリプション → 承認待ちのものを選んで

  注意点
  - ローカルのコミットを GitHub に push していない（プレイページ、セキュリティ、
    ドメイン対応など）。push すると GitHub Pages 版も新しい内容に変わる

  - サイト用 S3 の中身はデプロイのたびに web/ と同じ内容に上書きされる。手で編集しない
  - CloudTrail の保存用 S3 バケットは、スタックを消しても残る設定（記録を守るため）
  - Photon の AppId は WebGL のビルドに含まれ、隠せない。AWS 版サーバーへの移行が根本対策
  - CSP は「報告のみ」。違反が出ないことを確かめてから強制に切り替える
