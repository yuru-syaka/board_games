「駒が消えるマルバツゲーム」を作った話

2026.10.12 Unity ゴースト・マルバツゲーム

こんにちは、ゆるめの社会人です。unityroom で ゴースト・マルバツゲームを公開しました。 この記事では、作ろうと思ったきっかけと、ゲームの仕組みについて書きます。

作ろうと思ったきっかけ

三目並べは、ルールを覚えると先手も後手もミスをしなくなり、ほとんど引き分けになってしまいます。 「最後まで勝負がつく三目並べ」にできないかと考えたのがスタートです。

ルールの工夫：駒が消える

自分の駒は最大3個までにして、4個目を置くといちばん古い駒が消えるようにしました。 盤面が埋まらないので引き分けがほとんどなくなり、「どの駒が次に消えるか」を読み合うゲームになります。

なぜ「3個まで」なのか

3個にしたのは、三目並べで勝つにはちょうど3個が1列に並ぶ必要があるからです。 2個までだと並べようがなく、4個以上だと盤面が埋まりやすくなって、ふつうの三目並べに近づきます。 3個までにすると、「3個目を置いた瞬間に、1個目が消える」ことになり、 いつも手元の3個だけで1列を作るゲームになります。古い駒を足場にして勝つことはできません。

細かい決まりを、作りながら決めた

実際に遊んでみると、ルールの文章だけでは決まっていないところがいくつも出てきました。

  • 消える駒のマスには、同じ手で置けない：4個目を置くとき、消える予定の駒はまだ盤の上にあります。そのマスに置き直して「動かす」ような手はできないことにしました。
  • 勝ちの判定は、消えたあとの3個で行う：新しい駒を置き、古い駒が消えたあとに、残った3個が1列なら勝ちです。消える駒を数えて勝つことはできません。
  • 100手で引き分け：おたがいにふさぎ合うと、終わらないことが理論上はありえます。そこで、100手で引き分けにしました。実際にはほとんど起きません。

こうした決まりは、ルールの説明（ゲーム内の「あそびかた」と紹介ページ）にも同じ言葉で書き、 画面の動きとずれないようにしています。

Unityでの実装

置いた順番をキューで管理する

プレイヤーごとに、置いたマスを Queue に入れておきます。 4個目を置く前に一番古いものを取り出して消すだけで、「古い順に消える」が実現できます。 

// プレイヤーごとの「置いたマス」の履歴
private readonly Queue<int>[] history = { new Queue<int>(), new Queue<int>() };
private const int MaxPieces = 3;

void PlacePiece(int player, int cell)
{
    var queue = history[player];
    if (queue.Count >= MaxPieces)
    {
        int oldest = queue.Dequeue();   // 一番古い駒を取り出す
        board[oldest] = Empty;          // 盤面から消す
        cells[oldest].FadeOut();        // 消える演出
    }
    queue.Enqueue(cell);
    board[cell] = player;
}
Queue（キュー）は「先に入れたものから先に出てくる」入れ物です。順番が大事なゲームのしくみと相性が良いです。

次に消える駒を薄くする

queue.Peek() で次に消える駒が分かるので、その駒の透明度を下げて表示しています。 プレイヤーが先を読みやすくなり、遊びやすさが大きく変わりました。

CPU：6手先まで読む

このゲームは、運の要素も隠れた情報もない「完全情報ゲーム」です。そこで CPU は、 打てる手を順に試して何手か先まで読む、昔からある方法（アルファベータ探索）で手を選びます。 盤が 3×3 と小さいので、6手先（自分と相手で3手ずつ）まで読んでも一瞬で終わります。

読み切れなかった局面は、点数をつけて比べます。点数のつけ方の工夫は次の3つです。

  • 次に消える駒は数えない：2個並んでいても、片方が次に消える駒なら、もう並んでいないものとして扱います。このゲームならではの工夫で、これがないと、すぐに消えてしまう並びを「あと1手で勝てる」と見まちがえてしまいます。
  • 相手にふさがれていない列だけを数える：相手の駒がある列は、もう自分の列にはならないからです。
  • まん中のマスを少し高く見る：まん中は縦・横・斜めの4本の列に関わる、いちばん強いマスです。

同じ点数の手がいくつかあるときは、読み始める前に手の順番を混ぜておき、毎回同じ手にならないようにしています。 いつも同じ打ち方をする CPU は、すぐに勝ち方を覚えられてしまうからです。

作ってみて分かったこと

  • ルールを1つ足すだけで、知っているゲームががらっと変わる
  • 「次に何が起きるか」を見せる演出は、遊びやすさに直結する
  • ルールの文章に書いていない「すき間」は、遊んでみて初めて見つかる。見つけたら、画面と説明の両方に同じ言葉で書く
  • CPU の点数のつけ方にも、そのゲームならではの考え方（ここでは「消える駒」）を入れないと強くならない

その後

この記事のあと、ゴースト・マルバツゲームは unityroom からこのサイト（BOARD PIA）の中に引っ越し、 ブラウザでそのまま遊べるようになりました。オンライン対戦も、自分で作った対戦サーバーで遊べます。 その話はサーバーレスで対戦サーバーを作った話に書いています。 今では、ほかにも9本のゲームがあります。
