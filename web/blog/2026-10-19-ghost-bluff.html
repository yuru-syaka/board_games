正体を隠すボードゲームと「推理する CPU」

2026.10.19 Unity ゴースト・ブラフ

こんにちは、ゆるめの社会人です。今回は ゴースト・ブラフの仕組みについて書きます。 自分のおばけの正体は見えるのに、相手のおばけの正体は「？」で隠れている、だまし合いのボードゲームです。

どんなゲームか

6×6 の盤で、1人が善玉4体・悪玉4体の合わせて8体を動かします。 相手の善玉を4体すべて取るか、自分の悪玉を4体すべて取らせるか、善玉を相手側の角から脱出させれば勝ちです。 「悪玉をわざと取らせる」という勝ち方があるので、取りにいくこと自体が危険になる。 ここが、このゲームのいちばん面白いところだと思っています。

見えない情報を「見えない形」で渡す

このゲームでは、プログラムの中でも「全部が見えている局面」と「あるプレイヤーから見た局面」を分けています。 プレイヤーから見た局面では、盤の上にいる相手のおばけの種類が Unknown（不明）に置き換えられます。 取ったおばけや脱出したおばけは公開情報なので、こちらは見えるようにしています。

画面も CPU も、この「プレイヤーから見た局面」しか受け取りません。 こうしておくと、うっかり画面や CPU に相手の正体を渡してしまう不具合が、仕組みの上で起きなくなります。

オンライン対戦でも同じ考え方で、相手の画面に送る局面は、相手から見た形（こちらのおばけの正体を伏せたもの）にしてから送っています。

CPU は「推理」する

CPU にも相手の正体は見えません。そこで、相手のおばけ1体ずつについて「善玉らしさ」を見積もっています。 手がかりにしているのは次の2つです。

  • そのおばけが、こちらの陣地（脱出口）に向かって前進した回数
  • いま脱出口のすぐ近くにいるかどうか

善玉は脱出を狙って前に出てくることが多い、という考え方です。 残っている善玉の数を、各おばけの「重み」で割り振って確率にしています。 

// 相手のおばけそれぞれが善玉である確率の見積もり
foreach (var g in view.Ghosts)
{
    if (g.Owner != opponent || !g.IsOnBoard) continue;
    _advanceCount.TryGetValue(g.Id, out int adv);
    double w = 1.0 + 0.3 * Math.Min(adv, 5);       // 前進した回数が多いほど重く
    if (GeisterBoard.DistanceToEscape(opponent, g.X, g.Y) <= 1) w += 0.5;  // 脱出口の近く
    weights[g.Id] = w;
    total += w;
}
// 残っている善玉の数を重みで割り振る
probs[id] = Math.Min(0.97, goodLeft * weights[id] / total);

CPU は合法手ごとに、この確率を使って「取ったら得か損か」「脱出されそうか」を点数にし、いちばん良い手を選びます。 点数には小さな乱数も足しているので、毎回まったく同じ動きにはなりません。

ブラフが効くようにする

この見積もりは「前に出てくるのは善玉」と考えるので、悪玉を堂々と前に出すと CPU はだまされやすくなります。 逆に、善玉を目立たないように動かすと、CPU はなかなか気づきません。 人間同士で遊ぶときの駆け引きを、CPU 相手でも少し味わえるようにしたかったのが、この作りにした理由です。

その他の決まりごと

  • おばけの配置は、両者ともランダムに決まります
  • 200 手で決着がつかなければ引き分けです
  • 善玉が上の角に着いたら「脱出」を押すと、その場で勝ちになります

作ってみて分かったこと

  • 隠れた情報があるゲームは、「誰に何を見せるか」を最初に決めておくと作りやすい
  • CPU は完璧に強いより、人間と同じように「動きから推理する」ほうが遊んでいて面白い
  • 推理の手がかりが分かれば、プレイヤーはそれを逆手に取ったブラフを楽しめる
