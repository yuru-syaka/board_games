「かぶせて、のみこむ三目並べ」の仕組み

2026.10.19 Unity ゴースト・ゴブル

こんにちは、ゆるめの社会人です。今回は ゴースト・ゴブルの仕組みについて書きます。 大・中・小のおばけを使い、大きいおばけで小さいおばけを「のみこめる」三目並べです。

どんなゲームか

3×3 の盤に、大・中・小のおばけを2体ずつ、1人6体持って戦います。 自分の番には「手持ちを置く」か「盤の上の自分のおばけを動かす」のどちらかをします。 大きいおばけは小さいおばけにかぶせられるので、すでに埋まったマスも奪い返せます。 普通の三目並べと違って盤面が固まらず、最後まで逆転があるのが特徴です。

駒の持ち方：マスごとの「積み重ね」

1つのマスには複数のおばけが重なるので、マスごとに「下から上へ並んだ駒の配列」として持っています。 見えるのは一番上の駒だけで、勝ち負けの判定も一番上の駒で行います。 手持ちの数は別に数えず、「大きさごとの持ち数 − 盤の上にある数」で計算しています。 持ち方を1か所にまとめておくと、数え間違いの不具合が起きにくくなります。 

// 1 手を適用する（動かす場合は、元のマスの一番上を取り除いてから行き先に積む）
var stacks = state.CopyStacks();
if (!move.IsFromHand)
{
    var from = stacks[move.From];
    var lifted = new Piece[from.Length - 1];       // 一番上を取り除く
    Array.Copy(from, lifted, lifted.Length);
    stacks[move.From] = lifted;
}
var dest = stacks[move.To];
var pushed = new Piece[dest.Length + 1];           // 行き先の一番上に積む
Array.Copy(dest, pushed, dest.Length);
pushed[dest.Length] = new Piece(mover, move.Size);
stacks[move.To] = pushed;

いちばん大事なルール：下から列が現れる

おばけを動かすと、その下に隠れていた相手のおばけが顔を出すことがあります。 そのとき相手の列がそろってしまったら、動かした側の負けです。 さらに、動かした先で自分の列もそろった場合でも、相手の列を優先しています。 判定の順番を「まず相手の列 → 次に自分の列」にするだけで、このルールを表せます。 

// 持ち上げて現れた相手の列を、自分の列より優先する
int[] line = GobbletState.FindLine(stacks, opponent);
if (line != null)
    result = GameResult.WinFor(opponent);          // 下から相手の列が現れた
else if ((line = GobbletState.FindLine(stacks, mover)) != null)
    result = GameResult.WinFor(mover);             // 自分の列がそろった
画面では、下に隠れたおばけをマスの下の点で表示しています。 「動かすと何が出てくるか」が分かるようにしておかないと、理不尽な負けに感じてしまうためです。

終わらない対局への備え

駒を動かせるゲームなので、お互いが同じ動きを繰り返すと対局が終わらなくなります。 そこで、80 手で決着がつかなければ引き分けにしています。 また、手番の人が動かせるおばけを1体も持っていない場合は、その人の負けとしています。

CPU：αβ探索で 3 手先まで読む

CPU は、相手の応手も考えながら数手先まで読む「αβ探索（アルファベータ探索）」で手を選んでいます。 標準では 3 手先まで読みます。 読み切れない局面は、次のような「点数」で良し悪しを見積もります。

  • 相手にふさがれていない列に、自分のおばけがいくつあるか（2つなら大きく加点）
  • 大きいおばけを手持ちにどれだけ残しているか
  • 手番の側は次に列を完成できるので、2つ並んだ列を少し高く評価する

同じ点数の手がいくつもあるときに毎回同じ手を選ばないよう、探索の前に手の順番をシャッフルしています。 これで、同じ局面でも CPU の打ち方に少しばらつきが出ます。

オンライン対戦

オンライン対戦では、部屋を作った側（ホスト）が正式な盤面を持ち、相手から届いた手が正しいかを確かめてから盤面を進めます。 通信で送るのは「どのマスの、どの大きさのおばけを、どこへ」という短い文字列だけです。

作ってみて分かったこと

  • 三目並べでも「駒の大きさ」と「動かせる」を足すだけで、終盤まで読み合いが続くゲームになる
  • 勝敗の判定は、どちらを先に調べるかという「順番」そのものがルールになることがある
  • 隠れた情報（下にいる駒）は、画面でさりげなく見せるだけで遊びやすさが大きく変わる
