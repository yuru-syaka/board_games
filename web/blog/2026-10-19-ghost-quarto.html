「渡す駒を選ぶ」四目並べと、ビットで数える特徴

2026.10.19 Unity ゴースト・クアルト

こんにちは、ゆるめの社会人です。今回は ゴースト・クアルトの仕組みについて書きます。 自分が置くおばけは相手が選び、相手が置くおばけは自分が選んで渡す、ちょっとふしぎな四目並べです。

どんなゲームか

4×4 の盤に、16体のおばけを置いていきます。おばけはどちらのプレイヤーの物でもありません。 縦・横・斜めのどれかに4体が並び、その4体に共通の特徴が1つでもあれば、最後に置いた人の勝ちです。 自分の番では「渡されたおばけを置く」と「次に相手が置くおばけを渡す」を続けて行います。

4つの特徴を 4 ビットで表す

おばけには「色（青／ピンク）」「大きさ」「頭の形（まる／しかく）」「中身（ぬりつぶし／すけすけ）」の4つの特徴があります。 それぞれ2択なので、1体のおばけを 0〜15 の数字（4 ビット）で表せます。 16体のおばけは、この 0〜15 がちょうど1つずつです。

こうしておくと、「4体に共通の特徴があるか」はビット演算だけで調べられます。 4体のビットを AND すれば「全員が持っている特徴」、OR してから反転すれば「全員が持っていない特徴」が分かります。 どちらかが 0 でなければ、そのラインはそろっています。 

// 4 体に共通する特徴を求める
public static void SharedBits(int a, int b, int c, int d, out int ones, out int zeros)
{
    ones  = a & b & c & d;                              // 全員が 1 の特徴
    zeros = ~(a | b | c | d) & QuartoPiece.AllBits;     // 全員が 0 の特徴
}
// ones か zeros が 0 でなければ「そろった」
盤には全部で 10 本のライン（横 4・縦 4・斜め 2）があり、置くたびにこの判定を行っています。 通信で送る盤面も、16 マスに入っている駒の番号（空きは −1）を並べるだけで済みます。

CPU：「置く + 渡す」をまとめて読む

このゲームの難しいところは、良い場所に置くだけでなく、相手に何を渡すかで勝負が決まることです。 そこで CPU は、「置く」と「渡す」を1つの手番としてまとめ、αβ探索で先を読んでいます。

  • 置いてそろうなら、必ずそこに置く
  • 相手がすぐにそろえられてしまうおばけは、渡さない
  • 深さ 1 から少しずつ深く読み、決められた量（ノード数の上限）まで読んだ中で、いちばん深い結果を使う

読む量を「時間」ではなく「調べた局面の数」で区切っているので、同じ局面なら同じ考え方になり、不具合の調査もしやすくなっています。 終盤は残りのおばけが少ないので、最後まで読み切れることもあります。

画面での工夫

  • 置く前・渡す前に、もう一度クリック（または「決定」）で確定する2段階にして、押し間違いを防いでいます
  • そろいそうなラインが分かるよう、盤面の光り方で見せています
  • 先手は最初に「相手が置くおばけを渡す」ところから始まるので、その案内を画面に出しています

作ってみて分かったこと

  • 特徴が2択の組み合わせなら、ビットで表すと判定がとても短く書ける
  • 「何を渡すか」まで含めて1手と考えると、CPU の考え方を素直に作れる
  • 自分の駒がないゲームは、最初は分かりにくい。ルールの説明と画面の案内が特に大切
