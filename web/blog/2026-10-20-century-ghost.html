魂を集めておばけを呼ぶ「拡大再生産」の作り方

2026.10.20 Unity センチュリー・ゴースト

こんにちは、ゆるめの社会人です。今回は、新しく追加した センチュリー・ゴーストの仕組みについて書きます。 術カードで4色の「魂」を集め、交換し、強化して、おばけを呼び出すカードゲームです。

どんなゲームか

自分の番にできるのは「術を使う」「術を覚える」「おばけを呼ぶ」「休む」のどれか1つだけ。 術を覚えるほど魂の集まり方が強くなっていく、いわゆる拡大再生産のゲームです。 どちらかがおばけを4体呼んだラウンドで終わり、おばけ・コイン・黄以外の魂の合計点で勝負します。

魂は「色ごとの個数」で持つ

魂は 黄 ＜ 青 ＜ 桃 ＜ 紫 の4色で、ランク 0〜3 として扱っています。 1つずつの魂を並べて持つのではなく、色ごとの個数の組として持ち、 「足す」「引く」「何倍かする」といった計算をこの組に用意しました。

  • 召集：カードの魂を足す
  • 交換：左の魂を引いて右の魂を足す。何回くり返すかは倍数で計算する
  • 強化：指定した魂を1つ減らし、1つ上の色を1つ増やす

この組は一度作ったら中身を変えない（不変）ようにしています。 CPU が「この手を打ったらどうなるか」を何通りも試すとき、元の状態を壊す心配がなくなります。

術カードを取るときの支払い

市場の術カードは、左端ならタダで取れますが、右のカードほど高くなります。 k 番目のカードを取るには、左にある k 枚のカードに魂を1つずつ置く必要があり、 取ったカードの上に置かれていた魂は、取った人がもらえます。 置く魂は、プレイヤーが選ぶのではなく、ランクの低いものから自動で選ぶようにしました。 操作の手間を減らすためです。 

// 市場の i 番目の術カードを取る
var pay = spirits.Lowest(i);                 // 低い魂から i 個を選ぶ
spirits = spirits.Minus(pay);
for (int j = 0; j < i; j++)                   // 左の i 枚に 1 つずつ置く
    marketSpirits[j] = marketSpirits[j].Plus(Spirits.One(pay.RankAt(j)));
spirits = spirits.Plus(marketSpirits[i]);      // 取るカードの上の魂はもらえる
hand.Add(market[i]);
market.RemoveAt(i);
marketSpirits.RemoveAt(i);
持てる魂は最大10個です。あふれたときは、低い魂から捨てるようにしています。 画面でも「魂があふれます」と先に知らせるので、うっかり強い魂を失うことはありません。

見えない情報：山札の順番

術カードとおばけカードの山札の並び順は、どちらのプレイヤーにも見えません。 そこで、画面と CPU には「あるプレイヤーから見た状態」だけを渡し、山札は残り枚数だけが分かるようにしています。 CPU が山札の次のカードをこっそり知ってしまう、ということが仕組みの上で起きません。

CPU：1手先を読んで点数で選ぶ

CPU は、打てる手をすべて試し、打ったあとの自分の状態を点数にして、いちばん良い手を選びます。 点数は次のものを合わせて計算しています。

  • すでに取ったおばけとコインの点数
  • 持っている魂の価値（高い色ほど高い）
  • 場に並んでいるおばけを、あとどれくらいで呼べるか（近さ）
  • 手札や覚えた術カードの価値

終盤（どちらかのおばけが4体に近づいたときや、手数が多くなったとき）は、術カードの「これから役に立つ価値」を軽く見るように切り替えています。 さらに最後の手番では、残った魂を点数としてだけ数えます。もう術を使う機会がないからです。

そのほかの決まりごと

  • 先手は黄の魂3個、後手は4個で始まります
  • おばけが4体そろっても、手番が先手に戻るところ（そのラウンドの終わり）まで続けます。こうすると、先手と後手の手番の数が必ず同じになります
  • 200 手で決着がつかなければ終わりにします（終わらない対局を防ぐため）

作ってみて分かったこと

  • 種類の決まった資源は、「個数の組」で持つと計算も比較もすっきり書ける
  • 支払いを自動で選ぶと操作は楽になる。そのぶん、何が起きたかを画面で丁寧に見せることが大切
  • 拡大再生産のゲームは、序盤の「何を覚えるか」が後半を大きく左右する。CPU にもそれを見込ませる必要がある
