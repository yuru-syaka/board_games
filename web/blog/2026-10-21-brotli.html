ゲームのダウンロードを約3割軽くした話（Brotli 圧縮）

2026.10.21 Unity WebGL AWS

こんにちは、ゆるめの社会人です。今回はゲームそのものではなく、ゲームを届ける仕組みの話です。 このサイトの6本のゲームは、Unity で作ってブラウザで遊べる形（WebGL）にしています。 その配信のしかたを見直して、最初に読み込むデータを約3割小さくしました。

ブラウザで遊ぶゲームは「最初の読み込み」が重い

Unity の WebGL ビルドは、主に次の3つのファイルでできています。

  • .wasm：ゲームのプログラム本体（WebAssembly）
  • .data：画像や音などのデータ
  • .framework.js：ブラウザとゲームをつなぐ JavaScript

圧縮しないと、この3つで1本あたり約69MBあります。 そのままでは重すぎるので、もともと gzip で圧縮して配信していました。

これまでのやり方：JavaScript で展開していた

圧縮したファイルは、サーバーが「これは圧縮してあります」というヘッダー（Content-Encoding）を付けて返せば、 ブラウザが自動で展開してくれます。 ただ、最初はサーバー側の設定なしで動かしたかったので、Unity の Decompression Fallback という機能を使っていました。 これは、ヘッダーがなくても、Unity のローダー（JavaScript）が自分でファイルを展開してくれる機能です。

手軽な反面、展開をブラウザ自身ではなく JavaScript で行うので、そのぶん時間がかかります。 また、圧縮の方式も、どこでも展開しやすい gzip にしていました。

Brotli に切り替えて、ブラウザに展開させる

今は自分でサーバー（AWS の S3 と CloudFront）を用意しているので、ヘッダーを付けられます。 そこで、次のように変えました。

  • 圧縮の方式を、gzip よりよく縮む Brotli にする
  • Decompression Fallback をやめ、ブラウザ自身に展開させる

ビルドの設定は、この2行を変えただけです。

PlayerSettings.WebGL.compressionFormat = WebGLCompressionFormat.Brotli;
PlayerSettings.WebGL.decompressionFallback = false;

どれくらい小さくなったか

6本とも、ほぼ同じ結果でした。1本あたりの3つのファイルの合計です。 （gzip は、同じファイルを最高の圧縮率で圧縮し直して比べています）

  • 圧縮なし：約 68.9 MB
  • gzip：約 23.8 MB
  • Brotli：約 17.1 MB（gzip より約 28% 小さい）

いちばん大きいのはプログラム本体の .wasm で、約 51MB が約 9.8MB まで縮んでいます。 さらに、展開をブラウザに任せたことで、JavaScript での展開の手間もなくなりました。

つまずいたところ：ファイルごとに違うヘッダーが必要

Brotli のファイルをブラウザに展開させるには、ファイルごとに2つのヘッダーが必要です。

  • Content-Encoding: br：「Brotli で圧縮してあります」
  • Content-Type：展開したあとの中身の種類（.wasm なら application/wasm、.js なら application/javascript など）

ところが、S3 にファイルを上げるときに使っている AWS CDK の BucketDeployment は、 1回のアップロードに1種類のヘッダーしか付けられません。 そこで、アップロードを「.wasm.br」「.js.br」「.data.br」「それ以外」の4つに分けました。 

// 種類ごとにアップロードを分け、それぞれに合ったヘッダーを付ける
new BucketDeployment(this, 'Wasm', {
  ...common,
  exclude: ['*'],
  include: ['*.wasm.br'],          // .wasm.br だけを対象にする
  contentType: 'application/wasm',
  contentEncoding: 'br',
});
アップロードを分けるときは、「古いファイルを消す」処理がお互いのファイルを消さないように気をつけます。 include と exclude で対象を絞ると、消す処理もその範囲だけに効くので、4つを同じフォルダに置いても大丈夫でした。 また、.br のファイルを先に置いてから最後に index.html を差し替えるようにして、 新しいページがまだ置かれていないファイルを読みにいくことがないようにしています。

確かめたこと

  • 6本すべてのファイルに Content-Encoding: br と正しい Content-Type が付いている
  • ブラウザで開くと、自分で展開して、ゲームが起動する
  • 古い gzip のファイルは、サーバーから自動で消えている

作ってみて分かったこと

  • サーバーを自分で用意できるなら、Decompression Fallback より、ヘッダーを付けてブラウザに展開させるほうがよい
  • Brotli は gzip より手間が少し増えるが、その分しっかり小さくなる
  • ゲームの中身を変えなくても、「届け方」を変えるだけで遊ぶ人の待ち時間を減らせる
