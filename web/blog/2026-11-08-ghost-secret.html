手札1枚の推理ゲームで「だれが何を知っているか」を扱う

2026.11.08 Unity オンライン対戦 ゴースト・シークレット

こんにちは、ゆるめの社会人です。10本目のゲームとして、 ゴースト・シークレットを追加しました。 手札を1枚だけ持ち、1枚引いて1枚出しながら、相手が持っているおばけを推理して脱落させるカードゲームです。 今回は、このゲームならではの「だれが何を知っているか」の扱い方を中心に書きます。

どんなゲームか

カードは9種類・全18枚。自分の番には山札から1枚引き、2枚のうち1枚を出して効果を使います。 相手の数字を言い当てる、手札をこっそり比べる、のぞいて交換する、といった効果で相手を脱落させ、 最後まで残るか、山札が尽きたときに大きい数字を持っていればラウンドの勝ちです。 2〜4人で遊べて、CPU対戦とオンライン対戦の両方に対応しています。

カードは自分で考えた

手札1枚の推理ゲームという種類は「ラブレター」と同じですが、カードの種類・枚数・効果はこのゲームのために考えました。 考えるときに気をつけたのは、次の2つです。

  • 情報が動くカードを多くする：ササヤキは外れると相手に手札を見られる、ウワサは全員の手札が回る、など、だれかが何かを知るきっかけを増やしました。
  • 「出せないカード」と「手放すと負けるカード」を両方入れる：0のノロイは自分から出せず、フキトバシで捨てさせた人のほうが脱落します。8のヒミツは手放すと脱落します。どちらも、持っていることを知られると状況が大きく変わります。

バランスは、CPU どうしの対局を人数ごとに300局ずつ回して確かめました。 途中で止まる対局がないこと、カードが18枚のまま増えも減りもしないこと、 かけらを決まった数集めた人が出るか、30ラウンドの打ち切りで必ず終わることをテストにしています。

「知っている手札」をカードの番号で持つ

このゲームでは、ササヤキが外れたとき、アカリでのぞいたとき、クラベで比べたときなどに、 ある人が別の人の手札を知ることがあります。でも、その手札はすぐに動きます。 相手がそのカードを出したり、ウワサで手札が回ったり、フキトバシで引き直したりするからです。

そこで、18枚のカードに0〜17の番号をふり、各プレイヤーは「だれの手札がどの番号か」を覚えるようにしました。 数字ではなくカードの番号で覚えるのがポイントです。 手番が終わるたびに「その人はまだその番号のカードを持っているか」を確かめ、持っていなければ忘れます。 

// 手番のあとに、古くなった知識を消す
for (int p = 0; p < players; p++)
    for (int q = 0; q < players; q++)
    {
        int card = known[p][q];          // p が知っている q の手札（-1 は知らない）
        if (card < 0) continue;
        if (q == p || isOut[q] || !hand[q].Contains(card))
            known[p][q] = -1;            // もう持っていないので忘れる
    }

こうすると、カードが動く効果ごとに「だれの知識を消すか」を書かなくてすみます。 ウワサで回ったカードをだれかが知っていれば、渡した先を追う必要もなく、ただ忘れるだけです。 同じ数字のカードが5枚あるササヤキでも、番号で覚えているので「さっき見たあの1枚」を取りちがえることはありません。

できごとに「見てよい人」をつける

画面には「CPU1 が あなた の手札を見た」のような、そのラウンドのできごとを流しています。 ここで困るのが、だれに何を見せてよいかが、できごとごとにちがうことです。 アカリでのぞいた手札は、のぞいた人とのぞかれた人にしか見えません。クラベで比べた2枚は、比べた2人にしか見えません。

そこで、できごと1件ごとに「見てよい人」をビットの組（だれが見てよいかを1人1ビットで表した数）で持たせ、 画面や CPU に渡す前に、見てはいけない人のぶんはカードの中身を消すようにしました。 

// できごとを viewer の目線にする（見てはいけないカードは -1 にする）
public SecretEvent MaskedFor(int viewer) =>
    VisibleTo(viewer)
        ? this
        : new SecretEvent(Seq, Kind, Player, Target, -1, -1, Guess, Amount, Viewers);

「CPU1 が あなた の手札を見た」というできごと自体は全員に届きますが、 何のカードだったかは、見た本人と見られた本人にしか届きません。 推理ゲームでは「だれかが何かを知った」こと自体が手がかりになるので、できごとは消さずに、中身だけを隠しています。

オンライン対戦では、このできごとの記録も、手札も、サーバーでその席の人の目線に変えてから送っています。 ブラウザの通信をのぞいても、相手の手札は届いていません。CPU も同じ目線の情報だけで考えます。

CPU：見えていないカードを数える

CPU は、18枚から「自分の手札」「全員が出したカード」「表向きで脇に置いたカード」などの見えているカードを引いて、 まだ見えていないカードの枚数を数えます。手札を知っている相手は、その数字で確定として扱います。 知らない相手は、見えていない枚数の割合を、その人がその数字を持っている確率とします。

そのうえで、打てる手ごとに点数をつけて、いちばん良い手を選びます。

  • ササヤキ：その数字が当たる確率が高いほど高い点。手札を知っている相手には、その数字を言って当てに行きます
  • クラベ：自分が残すカードより相手の数字が小さい確率から、大きい確率を引いたもの
  • フキトバシ：相手がヒミツを持っていそうなら高く、ノロイを持っていそうなら大きく減点
  • 残すカード：山札が少なくなるほど、残すカードの数字を重く見る（山札が尽きたら数字の勝負になるため）

ヒミツを自分から出す手は、ルールでは出せますが CPU は選びません。 数えるだけの単純な CPU ですが、手札を知られたあとにササヤキを引かれると言い当てられるので、意外と手ごわく感じます。

オンライン対戦は2〜4人の部屋をそのまま使う

オンライン対戦は、前に作ったゴースト・ジュエルと同じ、2〜4人の部屋の仕組みにのせました。 ゲームごとに用意するのは、ルールの本体と「席ごとの目線で局面を文字列にする」部分だけです。 途中で抜けた人の席は CPU が代わり、90秒の手番の時間切れも、ほかのゲームと同じ決まりで動きます。

シャッフルは、対局ごとの種（シード）とラウンドの番号から乱数を作っています。 同じ種なら同じ配り方になるので、サーバーで対局をやり直して確かめることもできます。

見た目はゴースト・トレンドの部品を使った

タイトル画面・ボタン・ラウンドの結果・最後の結果の画面は、 ゴースト・トレンドと同じネオンの部品を使い、同じ並びにしました。 どの画面もシーンには置かず、すべてコードで組み立てています。新しく作ったのは、数字と名前とおばけの絵が入ったカードの部品と、 相手や数字を選ぶ操作の部分です。

作ってみて分かったこと

  • 情報が動くゲームでは、「知っていること」を物（カードの番号）にひもづけて持ち、古くなったら消すと、効果ごとの後始末がいらなくなる
  • 見せる・隠すは、表示の直前ではなくデータを渡す前に決めておくと、画面・CPU・サーバーのどこから見ても同じ答えになる
  • 「だれかが何かを知った」こと自体を見せると、推理の手がかりが増えて、ゲームが楽しくなる
