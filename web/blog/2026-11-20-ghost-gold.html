同時に決める押し引きゲームを、1人ずつの手番にのせる

2026.11.20 Unity オンライン対戦 ゴースト・ゴールド

こんにちは、ゆるめの社会人です。11本目のゲームとして、 ゴースト・ゴールドを追加しました。 おばけたちが夜の館を探検して金貨を集める、2〜5人の押し引き（どこまで粘るかを決める）カードゲームです。 今回は、このゲームの中心にある「全員が同時に決める」をどう作ったかを中心に書きます。

どんなゲームか

館の部屋のカードを1枚ずつめくり、金貨が出たら探検中の人で山分けします。 カードがめくられるたびに、全員が「進む」か「帰る」かを伏せて決め、一斉に公開します。 帰った人は手持ちを金庫に入れて安全にできますが、その夜はもう稼げません。 進んだ人は、同じ種類の怪異に2度出会うと、おどかされてその夜の手持ちをすべて失います。 これを5夜くり返し、金庫の金貨と秘宝の値打ちの合計で順位を決めます。

カードと決まりは自分で考えた

進むか帰るかを同時に決める押し引きという種類は「インカの黄金」と同じですが、 カードの枚数・数字・名前、お守りや秘宝の決まりは、このゲームのために考えました。

  • カードは31枚：金貨の部屋14枚（1〜14枚）、怪異4種類×3枚、秘宝5枚。
  • 秘宝は夜ごとに値打ちが上がる：1夜目の6枚ぶんから、5夜目は14枚ぶんまで。1人だけで帰った人がもらえます。後半ほど逆転のきっかけになります。
  • お守りは1人1回：おどかされたとき、手持ちが2枚以上なら半分を守れます。大きく負けている人が、もうひと粘りできるようにしました。

「同時に決める」を、1人ずつの手番にのせる

これまでの10本は、どれも「手番の人が1人ずつ手を打つ」ゲームでした。 オンライン対戦のサーバーも、時間切れの処理も、抜けた人の席を CPU が代わる仕組みも、 「今はだれの番か」が1人に決まっていることを前提にしています。 全員が同時に決めるゲームのために、これを作り直すのは大がかりです。

そこで、ルールの中では席の順に1人ずつ決めることにしました。 ただし、決めた中身はほかの人に見せず、探検中の最後の1人が決めた時点で、全員分を一斉に公開します。 先に決めた人の答えが見えないなら、順番に決めても、同時に決めるのと同じ遊び心地になります。 

// 決定を受け取ったら、次に決める人を探す。もういなければ公開する
s.Players[p].Choice = move.Choice;
s.Players[p].Decided = true;
s.CurrentPlayer = NextToDecide(s);   // 探検中で、まだ決めていない一番若い席
if (s.CurrentPlayer < 0) Resolve(s); // 全員決めた → 公開して、帰る人の処理と次の1枚

こうすると、サーバー側はほとんどそのまま使えました。 90秒の時間切れも、抜けた人の席を CPU が代わるのも、「今決める番の人」に対して、ほかのゲームと同じ決まりで動きます。

画面では、まだ決めていない人も「進む・帰る」をすぐ押せるようにしたい、という課題が残ります。 CPU 対戦では、自分の番が来るまで CPU の決定を先に進めておき、自分が押したら残りの CPU が決めて公開する、という流れにしました。 画面に出すのは「決めた」かどうかだけなので、遊んでいる側には同時に決めているように見えます。

ほかの人の決定は、公開まで届けない

順番に決める作りにした以上、先に決めた人の答えが後の人に漏れると、ゲームが成り立ちません。 そこで、画面や CPU に渡す局面を作るときに、自分以外の決定を「まだ決めていない」に書き換え、 山札の並びも全部伏せるようにしました。 

// あるプレイヤーの目線の局面を作る
var s = state.Clone();
for (int i = 0; i < s.Deck.Count; i++) s.Deck[i] = -1;          // 山札の順番は伏せる
for (int i = 0; i < s.PlayerCount; i++)
    if (i != viewer) s.Players[i].Choice = Choice.None;          // ほかの人の決定は伏せる

山札の「並び」は伏せますが、「内訳」はそのまま数えられるようにしています。 通路に出たカードと館から消えた怪異は全員に見えているので、残りの金貨や怪異の枚数は、人間でも数えれば分かるからです。 画面にはこの内訳から計算した「次の1枚でおどかされる確率」を出していて、帰りどきの目安になります。

オンライン対戦では、サーバーが席ごとにこの目線の局面を作ってから送ります。 さらに受け取る側でも、自分以外の決定に中身が入っている局面は読み込まずに捨てるようにしました。 送る側にまちがいがあっても、画面に答えが出てしまわないようにするためです。

CPU：似た CPU ばかりだと引き分けが増えた

CPU は、見えている情報から「進んだときの見込み」と「帰ったときの見込み」を比べて決めます。

  • 進んだとき：次の1枚が金貨である確率 × 金貨の平均 ÷ 残りそうな人数、に「まだ先へ進めることの値打ち」を足す
  • 帰ったとき：通路の余りの分け前と、1人だけで帰れそうなら秘宝の値打ち
  • 危険：おどかされる確率 × 失う手持ち（お守りで守れる分は引く）

最初はすべての CPU が同じ考え方でした。すると CPU どうしの対局を1,000局回したところ、 2人戦の45%が引き分けになりました。 同じ局面で同じ答えを出すので、2人がいつも同じときに帰り、金貨をぴったり同じだけ分け合ってしまうのです。

そこで CPU ごとに性格をつけました。危険をどれだけ重く見るか（慎重さ 0.4〜1.3）、 ほかの人がどれくらい帰ると読むか、どこまで粘るかを対局の最初にばらばらに決め、毎回の判断にも少し迷いを入れています。 これで引き分けは、2人戦で16%、3人以上では3〜6%まで減りました。 遊んでいても「この CPU は強気だな」「この CPU はすぐ帰るな」と分かるので、読み合いの相手としても面白くなったと思います。

テストでは、人数ごとに300局ずつ CPU どうしで最後まで遊ばせて、 途中で止まらないこと、5夜で必ず終わること、カードが31枚のまま増えも減りもしないことを確かめています。

見た目はゴースト・ジュエルの部品を使った

タイトル画面・ボタン・人数の選び方・結果の画面は、 ゴースト・ジュエルと同じネオンの部品を使い、同じ並びにしました。 新しく作ったのは、金貨・怪異・秘宝のカードの部品と、通路にカードを並べる部分です。 5人で遊ぶと通路のカードが多くなるので、18枚を超えたら1列に並べる数を増やして、画面に収まるようにしています。

オンライン対戦は、ゴースト・シークレットなどと同じ部屋の仕組みにのせ、 部屋の定員だけ5人に広げました。シャッフルは対局ごとの種（シード）と夜の番号から乱数を作るので、 同じ種なら同じ山札になり、あとから対局を再現して確かめられます。

作ってみて分かったこと

  • 同時に決めるゲームでも、答えを公開まで隠せば、1人ずつの手番の仕組みのまま作れる
  • 隠す処理は送る側だけでなく、受け取る側でも確かめると安心できる
  • 同じ考え方の CPU どうしは、同じ答えを出して引き分けになりやすい。性格の違いをつけると、勝負がつきやすくなり、相手としても読みがいが出る
