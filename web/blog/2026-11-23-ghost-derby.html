8倍が強すぎた。賭けのレースゲームのバランスを測って直す

2026.11.23 Unity オンライン対戦 ゴースト・ダービー

こんにちは、ゆるめの社会人です。12本目のゲームとして、 ゴースト・ダービーを追加しました。 真夜中の墓場を走る6体のおばけのレースに、魂コインを賭ける2〜5人のゲームです。 今回いちばん時間を使ったのは、ルールを作ることより、「8倍に賭けるだけで勝ててしまう」状態を直すことでした。

どんなゲームか

レースごとに、6体のおばけへ2倍・2倍・3倍・3倍・5倍・8倍の倍率を配ります。 全員が1体を選んでコインを伏せて賭け、手札のいたずら札を1枚、伏せたままレースの山札に混ぜます。 あとは山札を1枚ずつめくっておばけを進めるだけです。 先頭が6マスを越えると、そのときの順位で倍率が変わる追い賭けが1回あります。

1着は賭け金×倍率、2着は賭け金が戻り、3着以下は没収です。全3レースのあと、コインがいちばん多い人の勝ちです。 レースに賭けるという種類は「Hot Streak」と同じですが、倍率、走る札、追い賭け、いたずら札の内容はこのゲームのために考えました。

最初の調整は、いたずら札を数えていなかった

全員が同じ速さだと、いちばん配当が高い8倍に賭けるのが得になってしまいます。 そこで、おばけの倍率ごとに走る札の中身を変えることにしました。 走る札だけのレースを20万回試して、倍率が低いほど勝ちやすくなる組み合わせを選びました。数字の上では、8倍の1着は約6%です。

ところが実際に遊んでみると、どうも8倍が強い。そこで、 「いつも8倍に5枚賭けるだけ」の単純な作戦を作って、CPU 3体と3,000局戦わせました。 4人戦なので、公平なら勝率は25%です。

いつも賭ける倍率調整前の勝率調整後の勝率
2倍8.0%26.2%
3倍23.2%27.8%
5倍42.3%15.6%
8倍50.6%17.9%

原因は、いたずら札でした。自分が賭けたおばけに「ダッシュ」を使うと、もともと遅いおばけほど順位が大きく変わります。 さらに CPU は勝ちそうな2倍のおばけを邪魔するので、8倍のおばけは後押しされるのに狙われない状態になっていました。 走る札だけで測った数字は、実際の遊び方を映していなかったわけです。

実際の対局で組み合わせを探す

そこで、走る札の候補を総当たりして、いたずら札ありの CPU 対局で測り直しました。 難しかったのは、合計のマス数が1違うだけで勝率が大きく動くことです。 ゴールは12マスで、走る札を1周しても届かないおばけが多いので、「あと1マス」が結果を分けます。 ある組み合わせでは、5倍の札の合計を1増やしただけで、5倍に賭け続ける作戦の勝率が約13%から約49%まで跳ね上がりました。

最終的に選んだのは、倍率が上がるほど合計が1〜2ずつ減る、次の札です。

new[] { 2, 2, 2, 2, 3 }, // 2倍: 合計11。毎回2マス以上
new[] { 1, 1, 2, 2, 3 }, // 3倍: 合計9
new[] { 0, 1, 1, 2, 4 }, // 5倍: 合計8。休みと4マスがある
new[] { 0, 0, 1, 1, 5 }, // 8倍: 合計7。休みが2枚で、5マスの一発がある

8倍は「めったに勝てないけれど、当たると大きい」おばけになりました。 完全に平らにはできておらず、5倍は少し弱めです。5倍を強くする組み合わせも試しましたが、今度は5倍だけに賭ける作戦が勝率40%ほどになったので、 ひとつの作戦が突出しないほうを優先しました。

バランスを見るときは、平均の数字だけでなく、「これだけやれば勝てる」という単純な作戦を実際に戦わせると、抜け道が見つかります。 今回は1行のルールで書ける作戦が、いちばん正直な測定器になりました。

賭けた「額」も、コインの差から漏らさない

賭けは席の順に1人ずつ決めて、最後の人が決めたら一斉に公開します。 前作のゴースト・ゴールドと同じ作りですが、今回は気をつける点がひとつ増えました。 賭けた瞬間に持ちコインが減るので、賭けの中身を隠しても、コインの枚数の差から賭けた額が分かってしまうのです。

そこで、ほかの人に渡す局面では、公開前の賭けを消すだけでなく、コインも賭ける前の枚数に戻しています。

// 公開前の賭けは、額も分からないように、賭ける前のコインの枚数に戻して見せる
if (s.Phase == DerbyPhase.Bet && p.Decided)
{
    p.Coins += p.BetAmount;
    p.BetRunner = -1;
    p.BetAmount = 0;
}

オンライン対戦では、サーバーが席ごとにこの局面を作ってから送ります。 受け取る側でも、ほかの人の手札や公開前の賭けに中身が入っていたら、その局面を捨てるようにしています。

「2倍」と書くだけで、ずっと分かりやすくなった

最初の画面では、倍率を x2、x8 と書いていました。作っている本人には自然でも、遊ぶ側には分かりづらい表記でした。 そこで「2倍」「8倍」に直し、おばけと枚数を選ぶと結果を文章で出すようにしました。 

ルナに3枚 → 1着なら9枚、2着なら3枚戻る

また、倍率ごとの札の違いが見えないと、何を基準に賭ければいいか分かりません。 賭ける画面の各列にそのおばけの走る札5枚を並べ、倍率ごとの札といたずら札をまとめた「カード一覧」の画面も追加しました。

レースは一瞬で終わるので、一手ずつ見せる

このゲームのレースは、全員が決めたあとはカードをめくるだけです。ルールの計算は一瞬で終わるので、 そのまま画面に出すと、何が起きたのか分からないうちに決着してしまいます。

そこでルール側は「札をめくった」「おばけが動いた」「ゴールした」といった出来事の列を残し、 画面はそれを1件ずつ再生するようにしました。札が山札からめくられて列へ飛び、おばけが1マスずつ跳ねます。 ダッシュは光の尾を引いて突進し、つまずきは転がって戻り、金縛りは氷の色になって震えます。 

// 演出の長さ。CPU 戦はゆっくり、オンラインは持ち時間があるので少し速く
float Pace => (_pending.Count > 0 ? 0.4f : 1f) * (IsOnline ? OnlinePace : CpuPace);
const float CpuPace = 1.6f;
const float OnlinePace = 0.75f;

ルールと演出を分けてあるので、速さを変えてもゲームの結果には影響しません。 オンラインは1手90秒の持ち時間があるので、演出で考える時間を削らないよう、CPU 戦より短くしています。

作ってみて分かったこと

  • カードだけの確率では足りない。プレイヤーの行動まで含めた対局で測らないと、本当の強さは分からない
  • 「いつも同じことをするだけの作戦」は、バランスの抜け道を見つけるのに役立つ
  • 隠したい情報は、本体だけでなく、そこから計算できる数字も一緒に隠す
  • ゲームの中身が同じでも、表記と見せる速さで遊びやすさは大きく変わる
